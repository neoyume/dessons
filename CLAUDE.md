# Dessons — contexte projet

## Ce que c'est

Nom du projet : **Dessons** (contraction de "dessin" et "sons"). Repo GitHub prévu : `neoyume/dessons`.

Outil web mono-fichier (`index.html`, HTML + CSS + JS vanilla, zéro dépendance, zéro build) qui convertit une **image, une vidéo ou un flux webcam** en fichier `.mid` multi-pistes. Usage cible : générer des loops mélodiques/rythmiques à importer dans Logic Pro à partir d'un visuel (photo, illustration, texture, vidéo, caméra).

Deux sorties possibles : export d'un fichier `.mid`, ou lecture temps réel via **Web MIDI** vers un port virtuel (IAC Driver sur macOS) pour entendre/enregistrer la boucle directement dans Logic sans passer par un fichier.

Vidéo et webcam sont ré-analysées ~15 fps (`liveLoop()`) : les notes se recalculent en continu, la boucle MIDI suit l'image qui bouge. Bouton « Figer » pour capturer une frame.

Interface **bilingue FR/EN** (bouton `FR/EN`, détection `navigator.language` au 1er lancement, mémorisée en `localStorage` sous `dessons.lang`).

Tourne 100% dans le navigateur, aucune donnée envoyée à un serveur (l'image, la vidéo et le flux caméra ne quittent pas la machine). Pensé pour être publié tel quel sur GitHub Pages.

## Pourquoi ces choix (pour comprendre le code avant d'y toucher)

- **Pas de framework, pas de bundler** : `index.html` (l'atelier) + `compose.html` (la chanson) + `nodes.html` (la version modulaire) + `dessons-core.js` (code partagé), exprès. Le projet reste "ouvre et ça marche", copiable, forkable sans setup. Toute évolution doit si possible rester dans cette philosophie (ou alors le dire explicitement si on bascule vers un vrai build). `dessons-core.js` est un `<script src>` **classique, pas un module ES** (`type="module"` est bloqué en `file://`) : ses fonctions sont des globales, exactement comme quand elles vivaient inline dans `index.html`.
- **Encodage MIDI écrit à la main** (pas de lib type `midi-writer-js`) : format SMF type 1, multi-pistes, delta-times en variable-length quantity. Voir les fonctions `writeVarLen`, `buildMidi`. C'est volontairement bas niveau pour ne dépendre de rien et garder un contrôle total sur la structure du fichier.
- **Détection par contours/contraste, pas par pixel brut** : contrairement à la plupart des convertisseurs image→MIDI existants (qui prennent la couleur moyenne d'un bloc de pixels), celui-ci calcule un gradient de luminosité (différence entre pixels voisins) et ne garde comme "notes" que les zones où ce gradient dépasse un seuil réglable. Ça donne des résultats plus musicaux sur des images à formes nettes (dessins, silhouettes, textures graphiques) que sur des photos très douces/floues.
- **Séparation en calques → pistes/instruments** : par teinte (hue), par bande de luminosité, ou par couleurs choisies à la pipette (`sepMode='pick'`), chaque calque devient une piste MIDI distincte avec son propre canal, son patch General MIDI, et son nom. C'est la fonctionnalité différenciante du projet par rapport à l'existant. Boutons **M**/**S** (mute/solo) par calque : `layerAudible(i)` = `anySolo() ? L.solo : !L.mute` (solo prime sur mute, convention DAW). N'affecte QUE la lecture temps réel (scheduler des deux sinks) et l'affichage des points d'aperçu (opacité) ; **`buildMidi()` écrit toujours tous les calques** (le `.mid` est le document complet, le mixage se fait dans le DAW).
- **Pipette de calque** : `process()` calcule `pr/pg/pb` (RGB ajusté par le pipeline ci-dessous, `adjustPixel()`) en plus de `lum`/`hue`. En `sepMode='pick'`, `layerOf(px)` **isole** plutôt que partitionne : un pixel rejoint le calque pipetté le plus proche **seulement si** la distance RGB² est ≤ `pickTol²` (slider « Tolérance couleur », `#pickTol`, id `pickTolSq` dans le code) ; sinon `layerOf` renvoie `-1` et le pixel ne compte pour aucun calque (silence), au lieu de tomber dans un bucket « le plus proche » comme avant. Un calque dont la couleur n'a jamais été pipettée (`L.picked !== true`) est **exclu du test**, il ne peut jamais matcher par accident sur sa couleur placeholder — d'où le cas d'usage voulu : pipette le vert des feuilles, seul le vert joue, le rouge de la fraise reste muet. `if(nLayers===1) return 0` (raccourci hue/lum) ne s'applique **pas** en `pick` : avec 1 seul calque pipetté, l'isolation reste réelle (pas de retour à « tout »). UI : `pickLayer` (index armé, -1 = aucun) ; clic sur la pastille (devenue `<button>`, tirets tant que `!L.picked`) arme, clic sur `#preview` échantillonne (`adjCtx.getImageData` — on échantillonne ce qui est *affiché*, pas le pixel brut) et écrit `L.color`/`L.pickColor`/`L.picked=true`. La boucle de rendu (`for(x0..x1)`) fait `if(L<0) continue;` avant d'indexer `bestEdge[L]`. `L.pickColor`/`L.picked` survivent aux changements de `sepMode` ; `rebuildLayers()` les restaure en repassant sur `pick`. `#pickTolRow` (affiché/masqué dans `rebuildLayers()`) n'apparaît qu'en mode `pick`.
- **Pipeline de pré-traitement, ordre fixe** (inversion → lissage → courbe de tons → saturation, puis postérisation/seuillage au moment de l'assignation en calque) : `process()` lit les pixels bruts de `imgCanvas`, applique `invert` (`#invert`, `255-valeur`) puis, si `#blur`>0, `boxBlur()` (3 passes horizontale+verticale, fenêtre glissante O(w×h) donc indépendante du rayon — approxime un flou gaussien sans en payer le coût). Le but du flou est d'empêcher un pixel isolé bruité de déclencher une fausse note (voir `img-03-blur.png` dans les tests : passer `blur` à 5 sur une image bruitée fait chuter le nombre de notes parasites de moitié tout en révélant les vraies arêtes). Puis `adjustPixel()` (ex-`adjustRGB`) applique une **LUT 256 entrées** construite par `buildToneLUT(blackPt, whitePt, gamma)` — remplace l'ancien slider unique « Contraste » par 3 sliders (`#blackPt`, `#whitePt`, `#gamma`, gamma en `step="0.05"`, vrai float HTML, pas d'entier mis à l'échelle) ; les valeurs par défaut (21 / 234 / 1.00) reproduisent quasi exactement l'ancien contraste fixe à 120 %, pour la rétrocompatibilité visuelle. La saturation (`sat`) s'applique ensuite, inchangée. Résultat baké dans `adjCanvas`/`adjCtx` (un `putImageData` par `process()`) : `drawPreview()` dessine directement `adjCanvas` (fini le `pctx.filter='contrast(...)'` approximatif — l'aperçu montre maintenant exactement ce qui est analysé, flou et inversion inclus) et l'eyedropper y échantillonne aussi.
- **Seuil automatique (Otsu)** : bouton `#autoThresh` à côté de « Sensibilité ». `process()` mémorise `lastEdgeArr`/`lastMaxEdge` (le tableau de magnitude de gradient et son max, quel que soit le mode) ; au clic, `otsuThreshold()` (algo standard, maximise la variance inter-classes) tourne sur un histogramme 256 bins de ces magnitudes — **pas** sur la luminosité brute, parce que « Sensibilité » seuille un gradient relatif (`cutoff=(1-threshPct)*maxEdge`), pas un niveau de gris absolu. Le bin trouvé est reconverti en pourcentage (`threshPct = 1 - bin/255`) et écrit dans `#thresh` via un `dispatchEvent('input')` normal (aucun code dédié, réutilise le pipeline existant).
- ~~Postérisation (`#posterize`)~~ : contrôle retiré (feature supprimée sur demande explicite de l'utilisateur, "j'arrive toujours pas à comprendre son utilité réelle") — `layerOf()` en `sepMode='hue'` bucket directement sur `hue[px]` brut, sans quantification intermédiaire. Si le besoin refait surface (calques imprévisibles sur une image au hue bruité), l'ancienne implémentation quantifiait la teinte en N paliers avant le bucketing (`Math.floor(hue/hueStep)*hueStep`) — voir l'historique git si on veut la reprendre plutôt que la réinventer.
- **Méthode « Par contours (Sobel) »** (`sepMode='sobel'`, 4ᵉ option) : `sobelAt()` calcule un vrai gradient Sobel 3×3 (Gx/Gy, bords repliés) — plus lourd que le gradient simple `|Δx|+|Δy|` utilisé par `hue`/`lum`/`pick`, donc calculé **seulement** quand ce mode est actif (les autres modes restent inchangés au bit près). Comme un gradient n'a pas de « couleur » naturelle à répartir en calques, `layerOf()` bucket par **orientation** de contour (`atan2(gy,gx) mod π`, sur `nLayers` tranches) : chaque calque capture une famille de directions d'arête plutôt qu'une teinte — résultat en lignes/silhouettes, pas en zones pleines. Pas de downscale/spinner de chargement nécessaire : l'image d'analyse est déjà plafonnée à `MAXDIM=260px`, donc même Sobel + Otsu + flou tournent en quelques millisecondes.
- **Recadrage (zone d'intérêt)** : `cropRect` (`{x,y,w,h}` normalisé [0,1] sur le cadre source complet, `null` = image entière) est appliqué à la source dans `fitCanvas()` (dimensionne `imgCanvas` sur les proportions du crop, pas de l'image entière) et `grabFrame()` (`drawImage` 9-arguments pour n'extraire que ce sous-rectangle). Le reste du pipeline (`process()`, `adjCanvas`, l'export, le direction/curve, la pipette) ne sait même pas qu'un crop existe — il voit juste un `imgCanvas` plus petit, exactement comme avant cette fonctionnalité. Éditeur (`#cropBtn`/`#cropApplyBtn`/`#cropResetBtn`, panneau gauche) : glisser-déposer redessine `pendingCropRect` en entier (pas de poignées de redimensionnement — un nouveau drag remplace l'ancien, comme un outil de capture d'écran), pointer events sur `#preview` (`normPointFromEvent`/`rectFromPoints`), rendu par `drawCropEditor()` qui affiche le cadre **complet non recadré** assombri hors de la sélection (le point étant justement de voir ce qui sera exclu) — jamais `adjCanvas`, qui ne reflète que le crop déjà appliqué. `redrawPreview()` et la fin de `process()` basculent vers `drawCropEditor()` tant que `cropEditing` est vrai, pour qu'aucun autre contrôle (curseur, sens, courbe…) ne vienne écraser l'overlay pendant l'édition. `stopSource()` réinitialise toujours `cropRect`/`cropEditing` : changer de source repart d'un cadrage plein cadre.
- **Sensibilité par calque** : chaque `layers[i]` porte son propre `thresh` (1-100, mêmes unités que le slider global) et `threshCustom` (bool). Même idée que `L.auto` pour les noms : tant qu'un calque n'a pas eu son propre curseur touché, il suit le slider global en direct (`syncLayerThreshFromGlobal()`, appelé sur l'`input` de `#thresh`, met à jour `L.thresh` + le DOM de sa ligne sans tout re-render) ; dès qu'on le bouge, `threshCustom=true` et il se fige (icône `↺` pour revenir au global). Motivation : isoler une seule couleur (`sepMode='pick'` ou mute/solo) puis lui donner un seuil différent des autres calques, sans que ça n'affecte le reste. `process()` calcule `layerCutoffs = layers.map(L => (1-L.thresh/100)*maxEdge)` et l'utilise à la place de l'ancien `cutoff` unique dans la boucle de seuillage finale — chaque calque garde le même calcul de gradient/edge (inchangé), seul le seuil de sortie diffère. `rebuildLayers()` conserve `thresh`/`threshCustom` par index comme le reste (mute/solo/program), y compris entre deux images différentes.
- **Plage d'octaves en piano vu de dessus** (`#octaveStrip`, panneau Musique) : remplace les deux sliders "octave basse"/"octave haute" par une bande SVG (8 octaves de touches blanches/noires générées par `buildOctaveStrip()`) qu'on drag comme une sélection au marqueur (`pointerdown/move/up`, même idiome que le recadrage — `octaveFromEvent` = équivalent 1D de `normPointFromEvent`). `#octLow`/`#octHigh` restent la source de vérité, juste passés en `type="hidden"` : le strip ne fait que leur assigner une valeur et `dispatchEvent('input')`, donc `scaleNotesForRange()`, `resetControls()`, `CONTROL_DEFAULTS` etc. n'ont rien à savoir de son existence. `redrawOctaveHighlight()` repositionne un unique rect `#octHi` semi-transparent (pas de reclassement par touche) sur `input` de `octLow`/`octHigh` dans le hook `liveIds`. Pas de clic-pour-éditer ni de clavier sur ce contrôle (comme le recadrage) — c'est une sélection à la souris/tactile assumée.
- **Opacité image dans l'aperçu** (`#imgOpacity`, sous `.metaTransportRow`) : contrôle purement visuel, n'affecte jamais la détection de notes — `drawPreview()` applique `pctx.globalAlpha = imgOpacity/100` uniquement autour du `drawImage(adjCanvas,...)`, avant le fond noir semi-transparent fixe (`.55`, inchangé) et les points de notes (leur propre alpha via `layerAudible`, inchangé). À 100 (défaut, rétrocompatible) l'apparence est identique à avant ; à 0 l'image disparaît complètement et il ne reste que les points colorés sur fond noir. Câblé en dehors de `liveIds` volontairement : un `input` dédié qui ne fait que `syncLabels()+redrawPreview()`, pas `process()` — changer l'opacité d'affichage ne doit pas relancer toute l'analyse pixel par pixel. Inclus dans `PRESET_KEYS` malgré ça (les presets passent par `dispatchEvent('input')`, qui déclenche ce listener dédié normalement).
- **`.metaTransportRow`** (sous l'aperçu) : Direction/Courbe à gauche, Recadrage + résolution/notes à droite (`justify-content:space-between`, `.transportIcons` en premier dans le DOM) — l'ordre gauche/droite a été inversé une fois après coup sur demande explicite, donc si ça re-change, c'est bien `.metaTransportRow > .transportIcons` puis `> .metaCol` qu'il faut réordonner, pas le CSS `order`.
- **Zone Source fusionnée** (`#previewWrap`) : les 3 boutons Image/Vidéo/Webcam (`.srcBtn`) et le texte d'aide au glisser-déposer (`#dropHint`) vivent maintenant **à l'intérieur** de `#previewPlaceholder`, l'état vide du même cadre qui affichera ensuite le média chargé — regroupe ce qui était 3 blocs empilés (rangée de boutons, texte d'aide, cadre de preview) en une seule zone, pour gagner en hauteur et éviter le message redondant "dépose ici" / "ton image apparaîtra ici" (l'ancien texte `previewPlaceholder` a été retiré, le `dropHint` suffit maintenant à lui seul). Un seul `#fileInput` (`hidden`) partagé par Image et Vidéo — son `accept` est réglé juste avant `.click()` (`image/*` ou `video/*`), donc `loadFile()` et son autodétection MIME/extension restent inchangés ; ces boutons ne sont visibles qu'en état vide (dans `#previewPlaceholder`, masqué dès qu'un média est chargé), donc aucun risque de rouvrir le sélecteur de fichier par erreur en cliquant sur le média lui-même. Le glisser-déposer est monté sur **`#previewWrap`** (pas tout `.panel-source` comme avant) via `previewWrap.addEventListener('drop', ...)`, et reste actif que la zone soit vide ou déjà chargée — déposer un fichier remplace directement le média en cours (`loadFile()` appelle déjà `stopSource()` en premier, donc une webcam active est coupée avant le nouveau chargement, sans code dédié). `updateSrcBtns()` cible `wb.querySelector('span')` (pas `textContent` direct, pour ne pas effacer l'icône SVG du bouton Webcam) et bascule `.active` sur les 3 boutons selon `srcKind`. **Bouton « × » overlay** (`#removeMediaBtn`, `position:absolute` en haut à droite de `#mediaBox`, empilé après les canvases dans le DOM donc naturellement au-dessus sans z-index dédié) : seul point d'entrée visible pour vider le média une fois chargé (avec le drag&drop) — `removeMedia()` (facteur commun avec l'ancien code de `toggleWebcam()` qui gérait déjà "cliquer Webcam pour l'éteindre") route par `stopSource()`, qui coupe déjà les pistes de `camStream` et détache la `<video>` ; ce chemin devient le SEUL moyen de couper la webcam une fois active, puisque les 3 boutons (dont Webcam) sont masqués tant qu'un média est chargé. `aria-label` traduit (`removeMediaLabel`) posé dans `updateSrcBtns()` (appelée aussi au changement de langue) ; élément `<button>` natif donc focusable et activable au clavier (Entrée/Espace) sans code dédié. En vidant l'état, `clearPreview()` efface aussi le piano roll et le masque de sensibilité (`drawPianoRoll()`/`drawSensitivityMask()`, toutes deux déjà structurées pour clear-avant-check) — bug latent corrigé au passage : sans ça, un masque resté activé ou le dernier piano roll dessiné restaient visibles par-dessus le placeholder vide après un retrait, un cas bien plus atteignable maintenant que le × rend "vider le média" praticable en un clic sur n'importe quelle source (avant, seul le re-clic sur Webcam déclenchait ce chemin).
- **Hauteur max du média affiché** (`#mediaBox`, 490px) : les images très hautes (portrait 9:16) rendaient le cadre de preview démesurément long — demande explicite de l'utilisateur. `canvas#preview` est passé de `width:100%` (remplissage forcé, quelle que soit la hauteur résultante) à `max-width:100%; max-height:490px; width:auto; height:auto;` : un élément remplacé (canvas, comme `<img>`) avec ces seules contraintes se redimensionne tout seul en préservant son ratio intrinsèque, sans distorsion — donc toujours plein cadre en largeur pour une image large/carrée (comportement inchangé), mais plafonné en hauteur pour un portrait, largeur réduite en conséquence. Piège évité : `#sensMask`/`#scanOverlay`/`#removeMediaBtn` sont `position:absolute; inset:0` — s'ils étaient restés calés sur `#previewWrap` (qui reste toujours pleine largeur du panneau, un `<div>` bloc ne rétrécit pas pour suivre un enfant remplacé plus étroit), ils se seraient étirés au-delà du canvas désormais plus étroit et centré, désalignant masque/scan-line/bouton × par rapport à l'image réellement visible. Fix : un nouveau `#mediaBox` (`display:inline-block`, `max-height:490px`) enveloppe les 4 (canvas, sensMask, scanOverlay, removeMediaBtn) et se réduit en `shrink-to-fit` à la taille réelle du canvas ; `#previewWrap` centre ce bloc via `text-align:center` (pas de flex, pour ne pas perturber le layout bloc existant de `#previewPlaceholder`, resté un enfant normal de `#previewWrap`). L'eyedropper (`preview.addEventListener('click', ...)`) et l'éditeur de recadrage (`normPointFromEvent`) lisent déjà `preview.getBoundingClientRect()` directement (pas celui de previewWrap), donc aucun changement requis là — ils continuent de fonctionner correctement quelle que soit la largeur réelle du canvas.
- **Couleurs d'identité en Cyan/Magenta/Jaune** (`rebuildLayers()`, modes `hue`/`sobel`/`pick`) : la teinte synthétique par calque (`hslToHex(360*i/n, 70, 55)`, purement décorative — sert à distinguer les calques dans l'aperçu/piano roll, pas la vraie couleur détectée, voir `.swatchDetected` plus bas) est maintenant décalée de +180° (`wheelHue = (360*i/n + 180) % 360`) — à 3 calques, l'ancienne répartition égale sur la roue tombait pile sur rouge/vert/bleu (0°/120°/240°), la demande explicite était cyan/magenta/jaune à la place (180°/300°/60°, soit exactement l'ancien résultat plus un demi-tour de roue). Répartition toujours égale pour tout `n`, seul le point de départ change — un total de 6 calques donne toujours 6 teintes égales, juste toutes décalées d'un demi-tour par rapport à avant.
- **Expérimental : Calques/Instruments à côté du média** (`.sourceMediaRow`, dans `.panel-source`) : la section « Calques / Instruments » (titre + `#layerList`) a quitté le bas du panneau Analyse (colonne de droite, 1/5 très étroite — les noms d'instrument y étaient tronqués à 2 caractères, ex. "Ac") pour s'installer **à droite du média**, toujours à l'intérieur de la colonne Source (3/5 du `.rack`), pas comme une 4ᵉ colonne du rack. `.sourceMediaRow` utilise `grid-template-areas:"srcHead layersHead" "media layers"` (colonnes `2fr 1fr`, ratio demandé explicitement après un premier essai à largeur fixe `260px`) plutôt qu'un simple 2-colonnes, pour que les titres `<h2>Source</h2>`/`<h2>Calques / Instruments</h2>` (`.srcHead`/`.layersHead`) partagent la même rangée d'en-tête au lieu que le second traîne plus bas, dans `.layersPanel` — aussi demandé explicitement après le premier essai. Les deux `<h2>` gardent le style `.panel h2` générique (sélecteur descendant, s'applique même si `.layersPanel`/`.mediaCol` ne sont pas eux-mêmes des `.panel`) mais `margin:0` leur est réappliqué (spécificité 2-classes pour battre `.panel h2`) : l'espacement vient uniquement du `row-gap:14px` de la grille, pas de la marge native du `<h2>`. `.mediaCol` regroupe tout ce qui était avant en haut du panneau (`#fileInput`/`#freezeBtn`/`#srcHint`/`#previewWrap`) sous la zone `media` ; un item de grille ne fusionne pas ses marges avec ses enfants, donc `#previewWrap` a perdu son `margin-top` (le `row-gap` du parent suffit) et `#freezeBtn`/`#srcHint` ont chacun un `margin-bottom:10px` pour garder un espacement correct avec `#previewWrap` les rares fois où ils sont visibles (vidéo/webcam active, erreur de chargement). `align-items:start` pour que chaque colonne garde sa propre hauteur (le média plafonne à 490px, la liste de calques peut être plus ou moins haute selon leur nombre) sans s'étirer pour matcher l'autre. Sous 1080px, `.rack` repasse déjà en une colonne (règle existante) ; `.sourceMediaRow` suit la même logique avec ses propres `grid-template-columns:1fr`/`grid-template-areas` en pile (Source → média → Calques/Instruments → liste). Aucun changement JS : `$('layerList')`/`$('layerSwatchStrip')` etc. ne dépendent pas de la position DOM, seulement de l'id.
- **Instruments en icônes** (`.instrPicker` dans chaque ligne `.layerMain`, remplace le `<select>` visible) : la colonne resserrée par le layout ci-dessus tronquait déjà les noms d'instrument ("Ac", "El"…) — plutôt que rendre un `<select>` custom (perte du vrai menu déroulant natif, de la navigation clavier, du support lecteur d'écran), le `<select>` **reste natif et fonctionnel**, juste rendu invisible (`opacity:0`) et étiré en `position:absolute; inset:0` par-dessus une `<span class="instrIcon">` purement décorative (`pointer-events:none`) — tout clic/tap/focus passe donc par le vrai select, qui ouvre le vrai menu du système avec les vrais noms complets ; seul l'état "fermé" au repos affiche une icône au lieu du texte, ce qu'aucune combinaison CSS ne permet de faire directement sur un `<select>` natif. `renderLayerList()` construit `.instrPicker` (icône + select) et une fonction locale `syncInstrIcon()` retape `instrIcon.innerHTML` (le markup SVG de l'instrument) + `instrPicker.title` (tooltip = nom traduit, seul endroit où le nom complet reste visible au repos) à chaque `change` du select ainsi qu'à la construction initiale — donc toujours synchronisé après un changement d'instrument, un preset, ou un changement de langue (`rebuildLayers()` re-render tout). `.layerMain` passe de deux colonnes `1fr` (nom + select) à `1fr 32px` (nom + icône carrée) : le nom de calque récupère tout l'espace que l'ancien `<select>` texte lui prenait.
  - **Icônes = SVG dessinés par l'utilisateur, inlinés** : historique — d'abord un SVG maison (dessiné par l'assistant) jugé trop peu ressemblant, puis un passage par des **emoji natifs** (`🎹`/`🪈`/`🥁`, `instrIcon.textContent`) pour gagner en reconnaissance sans dépendance, puis (état actuel) remplacé par **6 SVG que l'utilisateur a dessinés lui-même** (Illustrator, `icons.ai` à la racine) — piano / orgue / vibraphone / basse / flûte / steel drums. Stockés en dur dans `const INSTR_ICONS = {piano:'<svg…>', …}` juste au-dessus de `GM_INSTR` (chaque entrée porte `icon: INSTR_ICONS.<nom>`), **markup inline, pas de `<img src>` ni fichier externe** — le zéro-dépendance / `file://` tient. Le SVG est repris **verbatim** de l'export Illustrator (viewBox `0 0 78.8 80`, `class="st0"`/`"st1"` sur chaque forme, `transform` inclus) ; seule retouche locale : `class="ic-cut"` sur les formes qui doivent ressortir en découpe sombre (touches du piano et de la basse). **Recoloration entièrement en CSS** (`.instrIcon` dans `<head>`), l'utilisateur dessine en noir sur blanc mais le thème est sombre : `.st0/.st1 { fill: currentColor; stroke: var(--panel-2) }` (le contour dessiné devient un trait de séparation couleur fond, quasi invisible sur le pourtour, visible en interne sur le remplissage `currentColor`), `.ic-cut { fill: var(--panel-2) }`. `.instrIcon` suit exactement la convention des autres boutons-icônes de l'app (`.iconGroup button`) : `color: var(--text-dim)` au repos → `var(--text)` + `border-color: var(--accent)` au survol ; plus de `font-size` (dimensionnement via `.instrIcon svg { width:20px; height:20px }`). Faiblesse connue et acceptée : la flûte, dessin très fin, reste peu lisible à 20px — inhérent à la forme, pas un bug.
  - **Liste réduite à 6 instruments** : la liste GM initiale comptait 19 entrées ; à l'usage l'utilisateur a remarqué qu'"beaucoup se ressemblent trop" au **son**. Cause racine trouvée dans `timbreFor()` (le synthé Web Audio d'aperçu, plus bas dans le fichier) : plusieurs entrées de la liste tombaient dans la **même branche de timbre** et sonnaient identiques au bit près (Célesta/Vibraphone/Marimba/Boîte à musique/Cloches tubulaires/Xylophone partageaient tous la plage `prog 8-15` "mallets" ; Piano acoustique/électrique/Clavecin tombaient tous dans le `default` faute de branche dédiée). Plutôt qu'élargir `timbreFor()` avec plus de branches, la liste `GM_INSTR` a été réduite à exactement **6** (le nombre max de calques, `#layers` plafonne déjà à 6) en piochant **un seul représentant par branche distincte** : Piano acoustique (`default`), Orgue (`16-23`, sawtooth quasi 100% sustain), Vibraphone (`8-15`, triangle percutée sans sustain), Basse synthé (`32-39`, sine+sub, coupure grave), Flûte (`72-79`, sine soutenue et brillante), Steel drums (`===114`, seule branche en onde carrée). Bénéfice de bord : `rebuildLayers()`'s `GM_INSTR[i % GM_INSTR.length].prog` (déjà générique, aucun changement de code) donne maintenant un instrument par défaut **différent pour chacun des 6 calques max**, plus de doublon par défaut. Chacun des 6 a aussi son SVG dédié dans `INSTR_ICONS` (voir le point ci-dessus).
- **Presets** (`#presetBar`, entre le header et `.rack`) : `PRESET_KEYS` liste les ~20 contrôles couverts (tout Analyse + Musique + `playDir`/`curve`, **pas** mute/solo qui restent un état de mix éphémère comme documenté plus haut). `currentPresetValues()` lit ces contrôles **plus** un `layerOverrides` par calque (`program` + `thresh`/`threshCustom`, la sensibilité par calque) — c'est directement la demande initiale de l'utilisateur ("je vois vite les limites quand je veux travailler que sur une couleur") qui a motivé le fait d'inclure le per-layer dans les presets, pas juste les réglages globaux. Deux sources dans le même `<select>` : `BUILTIN_PRESETS` (tableau codé en dur dans `index.html`, noms bilingues `{fr,en}` — c'est le fichier que l'utilisateur édite lui-même pour ajouter ses presets « maison », `value="builtin:<index>"`) et les presets utilisateur (`localStorage['dessons.presets']`, JSON `{nom: {values, layerOverrides}}`, `value="user:<nom>"`). `applyPreset()` réutilise le pipeline existant partout où c'est possible (assigne puis `dispatchEvent('input')` sur chaque contrôle, comme `resetControls()`) — **sauf** `playDir`/`curve` : ce sont des `<input type="hidden">` pilotés par les boutons-icônes, pas par `liveIds`, donc `dispatchEvent('input')` dessus n'a aucun écouteur à déclencher ; `applyPreset()` les assigne directement puis appelle `renderTransportIcons()`/`toggleCurveEditor()` à la main. Enregistrer demande juste un nom (`prompt()`, pas de modale dédiée — cohérent avec le reste de l'app qui n'a pas de système de dialogue). `renderPresetOptions()` est appelée dans `setLang()` pour retraduire les noms des presets fournis et les libellés de groupe. **Export/Import** (`#presetExportBtn`/`#presetImportBtn`) : `localStorage` ne quitte jamais un couple navigateur+origine donné (pas de sync, rien entre `file://` et GitHub Pages, rien entre deux navigateurs) — Export sérialise `getUserPresets()` tel quel en `.json` téléchargeable (même mécanisme blob+`<a download>` que `buildMidi()`), Import relit ce JSON et fait un `Object.assign` dans les presets existants (donc un import = un merge, pas un remplacement total ; collision de nom → `confirm()` listant le nombre concerné avant d'écraser). Aucune validation de forme au-delà de "c'est un objet plain" — un JSON corrompu déclenche juste l'alerte d'erreur au `JSON.parse`, un JSON valide mais aux clés farfelues sera silencieusement ignoré champ par champ par `applyPreset()` (déjà tolérant aux clés manquantes). **5 presets fournis** (les 2 d'origine + 3 ajoutés sur demande, "aussi cool que les 2 premiers mais différents") — choisis pour couvrir des combinaisons encore inexploitées plutôt que des variantes proches : `sepMode` hue/lum/lum/sobel/sobel (`pick` exclu volontairement, un preset ne peut pas baker une couleur pipettée), les 5 courbes non-`custom` (linear/decel/swing/pulse/accel, une chacune) et 5 directions dont 2 diagonales (`tlbr`/`brtl`, absentes des 2 presets d'origine qui utilisaient toutes deux `lr`), 5 gammes différentes sans doublon (minPenta/majPenta/dorian/minor/wholetone). "Éclats rapides"/"Rapid Sparks" (sobel, seuil 85%, gate 35%) a été retouché une fois after-test : `layers:6`+`octLow:3/octHigh:7` produisait ~930 notes sur `test-image2.png` (une image de test volontairement bruitée, 300 pixels de bruit ajoutés) — ramené à `layers:4`+`octLow:4/octHigh:6`, ~97 notes sur une image réaliste (`test-image.png`) ; le comptage élevé restant sur l'image bruitée est un comportement déjà présent sur "Contours nets" (même famille `sobel`), pas un défaut propre à ce nouveau preset.
- **Grille temps/hauteur plutôt qu'un point par pixel** : l'image est découpée en `steps` divisions (temps) × N voies (hauteur, une par degré de la gamme choisie dans la plage d'octaves choisie). Ça évite d'avoir des centaines de micro-notes injouables, et ça garantit qu'on reste toujours sur la gamme (pas de fausses notes possibles).
- **Sens de lecture réglable, cardinal + diagonal** (`playDir` : `lr`/`rl`/`tb`/`bt`/`tlbr`/`brtl`/`trbl`/`bltr`) : le temps peut suivre n'importe lequel des 8 axes/sens d'une image (les 4 côtés + les 2 diagonales, dans les 2 sens). Modèle unifié dans `DIR_DEFS` (`readDir()` renvoie l'entrée courante) : chaque direction est une paire de fonctions affines `fwd(nx,ny) -> [τ,ρ]` / `inv(τ,ρ) -> [nx,ny]` sur des coordonnées image normalisées (`nx,ny ∈ [0,1)`, `τ`=fraction de temps, `ρ`=fraction de hauteur), `inv` étant l'inverse algébrique exact de `fwd` (vérifié par test). Convention hauteur : pour les 4 cardinales, top/droite = aigu (comme avant) ; pour les 4 diagonales, le calque de hauteur est l'AUTRE diagonale, avec le côté haut-droite = aigu — même logique « haut/droite = aigu » appliquée à 45°. `process()` produit toujours des notes `{step, midi, vel}` où `step` = ordre de lecture (0 = premier joué) : l'export `.mid` **et** le scheduler temps réel consomment `step` tel quel, direction-agnostiques — seuls `process()` (`fwd`, un seul passage pixel par pixel, plus de découpage rectangulaire par cellule) et `drawPreview()`/`drawPlayhead()` (`inv`, placement visuel) en tiennent compte. La tête de lecture et les points d'aperçu sont un simple segment `inv(τ,0)→inv(τ,1)` (droit même en diagonale, car `inv` est affine) ; le canvas clippe tout seul ce qui déborde du cadre près des coins.
- **Courbe de lecture** (`curve` : `linear`/`accel`/`decel`/`pulse`/`swing`) : `curveFrac(mode, k, n)` renvoie la fraction de boucle (0..1) où le pas `k` sonne (`stepTimeFrac(k,n)` = wrapper qui lit `$('curve').value`). Linéaire = `k/n` ; les autres courbent ça (accélérando, ritardando, dense-aux-bords, swing 1 pas sur 2). Consommé par le scheduler (durée de chaque pas = `loopMs * (stepTimeFrac(k+1) - stepTimeFrac(k))`), `drawPlayhead()` (via le ring buffer `stepWin` de `{step, at, span}`), `drawPreview()` (ticks sur le bord d'attaque) **et `buildMidi()`** (positions de tick courbées — la groove est baclée dans le `.mid`, contrairement au mute/solo). `linear` reproduit exactement l'ancien comportement.
- **`playDir` et `curve` = boutons-icônes** (pas des `<select>`) rendus par `renderTransportIcons()` à côté du bouton « Écouter l'aperçu » (panneau gauche). L'état vit dans deux `<input type="hidden">` (`#playDir`, `#curve`) → tous les `$('playDir').value` / `$('curve').value` marchent tels quels. `DIRS` liste les 8 directions (4 cardinales + 4 diagonales) avec leur tracé SVG (flèche/chevron, même style que les cardinales tourné à 45°) ; clic → `process()`. Clic courbe → `redrawPreview()` (6 ticks placés par `curveFrac`, l'icône EST la groove). `.iconGroup{flex-wrap:wrap}` en filet de sécurité pour les 8 boutons sur petit écran. Re-render sur changement de langue (tooltips).
- **Courbe `custom`** : `customPoints = [0,y1,y2,y3,1]`, 3 poignées libres à x fixe (.25/.5/.75). `customCurveY(p)` = interpolation linéaire par morceaux. Monotonie **garantie par construction** : au drag, `customPoints[i]` est clampé entre `customPoints[i-1]` et `customPoints[i+1]` (jamais l'inverse — on ne touche jamais aux voisins). Éditeur SVG (`#curveGraph`, 3 `<circle class="cp">`) câblé une fois par `initCurveEditor()` (pointer events + `setPointerCapture`), affiché/masqué par `toggleCurveEditor()`. Premier passage sur « Personnalisée » → `customPoints` initialisé depuis la courbe précédemment active (`customSeeded` évite de re-seeder ensuite). Ne jamais permettre à l'utilisateur de rendre la courbe non-monotone (durées de pas négatives → scheduler cassé).
- **Piano roll** (`#pianoRoll`, sous Direction/Curve dans la colonne Source) : remplace le compteur « X notes » par une grille step × hauteur qui redessine **`lastNotes`** tel quel (rien recalculé — le tableau qui sert déjà à `buildMidi()` et au scheduler temps réel). Axe X **linéaire en index de step**, pas en temps courbé par `curve` : c'est ce qui le fait lire comme un piano roll normal plutôt que comme un graphe déformé ; seule la tête de lecture suit la position réelle (courbée) de la boucle, donc une courbe « Pulsing » se voit à la tête qui s'agglutine aux bords de la grille sans que les notes elles-mêmes ne bougent. Largeur de note = Gate% (comme le calcul réel de durée de note dans le scheduler/export), couleur = celle déjà assignée au calque d'origine (aucune palette parallèle). `currentLoopPos(steps)` a été extrait de `drawPlayhead()` pour être partagé entre la tête de lecture sur l'image et celle du piano roll — les deux lisent le même ring buffer `stepWin`, donc jamais en léger désaccord l'une avec l'autre.

- **Courbe de tons interactive avec histogramme** (`#toneCurveGraph`, remplace visuellement les 3 sliders Black/White/Gamma — **remplacement explicite demandé**, contrairement au principe général « en plus, jamais à la place » qui s'applique aux 5 autres items de ce brief). Le graphe ne fait que lire/écrire `#blackPt`/`#whitePt`/`#gamma` (toujours la source de vérité, affichés en chiffres à côté) et appelle **`buildToneLUT()`**, la fonction déjà utilisée par `process()` — donc rétrocompatibilité garantie par construction, pas par test a posteriori : la courbe affichée EST la LUT réellement appliquée. `computeHistogram()` (luminosité 0-255, pondération standard 0.299/0.587/0.114) tourne **une seule fois par chargement d'image** (pas par frame), avec une échelle en racine carrée sur l'axe Y pour qu'un pic unique (fond uni) n'écrase pas visuellement le reste de la distribution. 3 poignées glissables : noir (bas-gauche, sur l'axe X), blanc (haut-droite), gamma (point milieu de la courbe, dérivé algébriquement de `0.5^(1/gamma)` — pas de recherche numérique, la position de la poignée et la valeur de `gamma` s'inversent exactement l'une dans l'autre). Réutilise **`dir.inv()`** et **`curveFrac()`**, les mêmes fonctions que `drawPlayhead()`/`buildMidi()` (aucune maths dupliquée, donc la démo ne peut pas mentir sur le comportement réel). - **Clavier sous Gamme/Note fondamentale** (`#scaleKeyboard`) : mini clavier une octave (12 touches), construit une fois (`buildScaleKeyboard()`) puis simplement re-teinté (`redrawScaleKeyboard()`) à chaque changement de `scale`/`root` — chaque `<rect>` porte un `data-semi` fixe, aucune reconstruction DOM au changement. Les degrés de la gamme (`SCALES[scale].map(d => (root+d)%12)`) reçoivent `--accent` à 50% d'opacité, la fondamentale reçoit `--cyan` à 100% — couleur ET intensité différentes, comme demandé, en réutilisant les deux teintes déjà dans la palette plutôt qu'une nouvelle couleur. Aucun calcul d'image impliqué (contrairement à tout le reste de cette section) : c'est une pure fonction gamme+fondamentale → indices de touches.
- **Pastilles de couleur détectée par calque** (`.swatchDetected` dans chaque ligne de « Calques / Instruments », `#layerSwatchStrip` sous le slider « Séparation en calques ») : distinctes de la pastille d'identité existante (`.swatch`, la couleur arc-en-ciel/synthétique par index utilisée pour les points de l'aperçu et du piano roll — qui reste inchangée, ces pastilles ne remplacent rien) — celle-ci montre la **vraie couleur moyenne** des pixels effectivement tombés dans le bucket de ce calque. Accumulée dans `process()`, dans la même passe pixel-par-pixel qui calcule déjà `layerOf(px)` (pas de second passage sur l'image) : `sumR/sumG/sumB/swCount` par calque, moyennés en `L.detectedColor` juste après la boucle. Moyenne sur **tous** les pixels assignés au calque (le bucket entier), pas seulement ceux qui passent le seuil de sensibilité et deviennent des notes — un calque à seuil très strict reste donc lisible (pas de pastille qui vire au noir) puisqu'elle répond à « qu'y a-t-il dans ce calque » plutôt que « qu'est-ce qui sonne là, maintenant ». `null` (bucket vide, aucun pixel n'y est jamais tombé) rendu en transparent — signal utile en soi (ex. teinte bleue jamais présente dans l'image). Mis à jour à chaque `process()` (donc aussi en direct sur vidéo/webcam) via `updateLayerSwatches()`, qui ne fait que retaper le `background` des éléments déjà en place (même idiome que `syncLayerThreshFromGlobal()`) — `renderLayerList()` ne reconstruit les pastilles (et le nombre de chips du strip) qu'au changement structurel du nombre de calques.

  - **Échelle des marques** : points et traits sont dimensionnés pour le canvas d'aperçu (`imgCanvas*3`, ≤780px) ; `markScale = box.w/preview.width * VIDEO_MARK_BOOST` (1.4) les remet à l'échelle du cadre d'export, le boost étant là pour qu'ils survivent au ré-encodage des plateformes. `alphaFor` est forcé sur `layerAudible()` seul : l'atténuation d'isolation au survol/pin est une affordance souris et n'a rien à faire dans un fichier.
  - **Durée = boucles entières** : `Math.max(1, Math.round(15000/loopMs)) * loopMs` — le nombre entier de boucles le plus proche de 15s, jamais une boucle tronquée, toujours au moins une (tempo lent / beaucoup de mesures). Le `MediaRecorder` démarre sur `playOriginAt` (nouveau : posé par `startPlayback()`, = l'instant où le pas 0 sonne) et **pas** au clic, sinon les ~90ms d'amorce de `startPlayback()` atterrissent en blanc en tête d'une vidéo que les plateformes rejouent en boucle. Vérifié : les frames espacées d'une boucle exacte sont identiques (diff moyenne 0.26/255).
  - **Audio** : `ensureVideoAudioTap()` branche un `createMediaStreamDestination()` **en parallèle** sur `synthOut` (= le compresseur, dernier nœud avant les haut-parleurs, désormais gardé en variable dans `ensureAudio()`). Le chemin haut-parleurs (`ac.destination`, ou l'élément `<audio>` iOS) n'est jamais débranché. Le son lo-fi du synthé fait partie de l'esthétique, rien à « corriger » ici.
  - **Watermark non désactivable** (ces clips circulent hors contexte) : « dessons » + `neoyume.github.io/dessons` en DotGothic16, `--accent` à 58 %, centré dans la bande du bas. Si le média remplit le cadre (portrait ≥9:16, aucune bande disponible), bascule en surimpression sur une plaque semi-transparente arrondie en bas de l'image — les deux cas ont été rendus et vérifiés visuellement.
  - **Garde-fous** : `startVideoExport()` reste **synchrone jusqu'à `startPlayback()`** (même règle iOS que `startPreviewPlayback()`, ne jamais y réintroduire d'`await`) ; `setVideoExportBusy()` désactive Export .mid / Play in DAW / Écouter l'aperçu pendant l'opération (un seul scheduler audio) et `videoExporting` est lu par `updatePlayBtnState()` ; `videoExportFrame()` s'arrête aussi sur `!playing` (média retiré, `pagehide`…) et rend ce qui a été capturé plutôt que de tourner dans le vide ; `visibilitychange` appelle `finishVideoExport()` puisque rAF ne tourne plus une fois l'onglet caché. `cleanupVideoExport()` ne stoppe **que** la piste vidéo — la piste audio appartient à `videoAudioTap`, réutilisé d'un export à l'autre.
  - **WebM, pas de MP4 côté client** (trop lourd en JS pur sans dépendance) : `video/webm;codecs=vp9,opus` si supporté, sinon vp8, sinon ce que le navigateur choisit (l'extension du fichier suit `videoRec.mimeType`). La note « convertis en MP4 pour publier depuis une app mobile » est dans le tooltip du bouton (`videoExportTitle`), pas en texte permanent — le header est déjà chargé. Si `MediaRecorder`/`captureStream` manquent, `videoExportSupported()` est faux, le bouton reste désactivé avec le tooltip `videoExportUnavail` et **tout le reste de l'app fonctionne normalement** (vérifié).

- **Trajet dessiné** (`playDir='path'`, 9ᵉ icône, 2026-10-21) : l'utilisateur trace une polyligne sur l'aperçu (`#pathBtn`, `setPathDrawing()`, pointer events à côté de ceux du recadrage ; premier clic sur l'icône sans trajet = mode tracé direct). `pathPoints` (normalisés) → `pathModel()` (rééchantillonné à `PATH_N` points à abscisse curviligne égale, en espace corrigé du ratio, mis en cache) ; `DIR_DEFS.path` : τ = position du point le plus proche sur la courbe, ρ = distance signée (à gauche du sens de marche = aigu), normalisée par `dmax` (pixel le plus loin de l'image) ; `inv` = point de la courbe + normale. `process()` lit une LUT par pixel (`pathLut()`) au lieu d'appeler `fwd` 58 000 fois, et accumule `cellCentroid` : en mode trajet, les points sont posés au centroïde des pixels de leur case (`notePos()`), car `inv()` d'un centre de case tombe hors des pixels là où la courbe s'enroule. Rail en pointillés néon, ticks de courbe centrés sur le rail. Sauvé dans les presets (`path`). Les 8 directions affines ne passent pas par ce code (rendu inchangé).
- **Style des notes** (`#noteStyle` : `dots`/`links`/`spring`/`water`, rangée « Notes », 2026-10-21) : `dots` = rendu historique, inchangé. Les autres passent par `paintNoteStyle()` (donc aussi l'export vidéo) : chaque note s'allume quand la tête de lecture la joue (âge calculé depuis `currentLoopPos()` + `stepTimeFrac()`), celles pas encore jouées dans la boucle restent pâles ; liens vers la note la plus proche du pas précédent du même calque, voisine choisie sur les positions **au repos** (sinon le rebond fait sauter les liens d'une image à l'autre) ; `spring` = rebond amorti, `water` = notes qui flottent, liens qui ondulent, ronds dans l'eau. Tailles en fraction de la largeur (`U = w/1080`). Hors lecture : tout au repos, tous les liens visibles. Repris du montage des reels Dessons (`2026_PromoSNS/Dessonslab/atelier/mont_app_calques.py`, `LIENS=`).

## Page Chanson (`compose.html`, branche `compose`, 2026-10-27)

**En stand-by depuis le 2026-11-05** (demande explicite : le mode Nodes prend sa place). `compose.html` reste dans le repo et marche toujours par son URL directe, mais plus aucun lien n'y mène. Dans `index.html`, `.songAction` (bouton « Ajouter à la chanson » + lien) est juste `hidden`, tout son code est intact : pour réactiver, retirer ce `hidden` et remettre le lien dans l'en-tête de `nodes.html`. À sa place, `a#nodesBtn` (`.step3` du bandeau) ouvre `nodes.html` ; c'est un simple lien, toujours actif, le média chargé dans l'atelier n'est pas transmis aux Nodes.

But : composer des morceaux (~1'30 d'abord, plus long ensuite) à partir de plusieurs images. Choix assumé : **un arrangeur de scènes, pas un multipiste DAW** — les calques d'une image sont déjà des pistes simultanées, ce qui manquait c'est la structure dans le temps (intro/couplet/refrain). Le mixage reste dans Logic.

- **Scène** = une boucle figée depuis l'atelier (bouton `#addToSongBtn` « Ajouter à la chanson », `.step3` du bandeau, `currentScene()` dans `index.html`) : `notes` (copie de `lastNotes`), ce qui les place dans le temps (`bars`/`steps`/`curve`/`customPoints`/`gate`), ce qui les affiche (`thumb` = JPEG de `adjCanvas`, `layers` = nom/programme/couleur/nom d'instrument FR+EN), plus `scale`/`root`/`tempo` (informatifs) et `preset` (`currentPresetValues()`, gardé pour pouvoir rouvrir la scène dans l'atelier plus tard — pas encore câblé). **L'image elle-même n'est pas stockée** et `compose.html` ne ré-analyse jamais rien : une scène sonne exactement comme l'export de l'atelier.
- **Stockage** : scènes dans IndexedDB (`dessons` / store `scenes`, helpers `loadScenes`/`saveScene`/`deleteScene` dans `dessons-core.js`) — pas `localStorage`, les vignettes dépasseraient vite ~5 Mo. Arrangement (`{tempo, loop, items:[{key, sceneId, repeats}]}`) dans `localStorage['dessons.song']`. L'atelier prévient un onglet Chanson ouvert via `BroadcastChannel('dessons-song')` (`notifyScenesChanged()`), et `compose.html` relit aussi les scènes au `focus` (filet pour `file://`/navigateurs sans BroadcastChannel). Un slot dont la scène a disparu est retiré au chargement. **Projet .json** (Sauver/Ouvrir) = scènes + arrangement : sauvegarde et seul moyen de passer d'un navigateur à l'autre ou de `file://` à GitHub Pages (stockages distincts).
- **Temps** : tempo **global** à la chanson (initialisé sur celui de la 1ʳᵉ scène ajoutée), chaque slot joue sa boucle `repeats` fois (`bars*4` temps par boucle, 4/4). `buildTimeline(items)` aplatit tout en notes absolues **en temps (beats)** `{layer, sec, midi, vel, on, span, dur}` via `curveFracAt()` sur le `steps`/`curve` propre à chaque scène — consommé tel quel par l'export, le scheduler et le canvas. Gamme/fondamentale : pas imposées (les notes sont déjà des hauteurs MIDI), mais un ⚠ signale un slot dont la tonalité diffère de la 1ʳᵉ scène.
- **Export** : `buildSongMidi()`, une piste par **index de calque** (calque 1 de chaque scène → piste 1…), program change à chaque début de section, noms de scène en **marqueurs** (`FF 06`, visibles dans la piste de marqueurs de Logic) sur la piste tempo. Nom de piste = nom du calque si toutes les scènes sont d'accord, sinon « Piste N ».
- **Lecture** : même planification juste-à-temps que l'atelier (25 ms / lookahead 150 ms) mais position tenue **en temps** (`schedBeat`) : changer le tempo ne fait que déplacer `startAt`, éditer l'arrangement en cours de lecture reconstruit `tl` sans perdre la position. `startPlayback()` reste **synchrone** (règle iOS). ▶ sur une carte = audition de la scène seule en boucle. Clic sur la timeline = lecture depuis cette mesure. Pas de Web MIDI ici pour l'instant (l'export .mid couvre l'usage Logic).
- **Pistes suivantes** : rouvrir une scène dans l'atelier (via `preset`), Web MIDI vers Logic, transitions entre scènes, scène vidéo longue, export vidéo de la chanson.

## Page Nodes (`nodes.html`, branche `nodes`, 2026-11-02)

Version modulaire de l'atelier : le même pipeline découpé en nodes reliés par des fils typés, sur un canvas qu'on déplace/zoome. L'atelier reste intact, c'est une 3ᵉ page. Le but : brancher, empiler et recombiner les étapes que l'atelier impose dans un ordre fixe (deux filtres de calque à la suite, un balayage par calque avec son propre sens/nombre de pas → polyrythmie, une gamme partagée par plusieurs balayages).

- **Types de fils** (couleur du port) : `image` `{w,h,data}` RGBA ≤ `MAXDIM` · `field` `{w,h,rgb,lum,hue,sat,edge,angle,maxEdge,mask}` (carte de contours + les pixels concernés) · `scale` `{pitches,scale,root}` · `notes` `{steps,curve,notes:[{step,midi,vel,row}],rows,field,dir}` · `track` = notes + `{name,program,color,mute}` · `path` `{points}` · `curve` `{pts}`. Une entrée n'accepte qu'un fil de même type ; seule l'entrée `tracks` de Boucle est multiple (ordre de branchement = ordre des canaux/pistes). Une `image` qui sort directement d'une Source porte aussi `{orig, region}` (le média pleine résolution + la zone affichée) : c'est ce qui permet au Recadrage de ré-échantillonner net.
- **Nodes** (`NODE_DEFS`, chacun `inputs/outputs/params/compute/thumb`) : Sources, trois nodes distincts (`srcImage` « Choisir une image » ; `srcVideo` « Choisir une vidéo » + Figer, ~15 fps ; `srcWebcam` Allumer/Éteindre + Figer, ~15 fps ; `srcMesh` voir plus bas ; Figer met aussi en pause l'élément `<video>`, sinon un Recadrage en aval relirait l'image en cours ; en-tête bleu pur `#0000ff`, `isSource(n)` les reconnaît, un graphe ancien de type `source` est relu en `srcImage`) → Recadrage (glisser sur la vignette, double-clic = image entière ; recadre le média d'origine **avant** la réduction à `MAXDIM` comme l'atelier, sinon — placé après un traitement — rogne les pixels reçus), Tons (noir/blanc/gamma/saturation, `buildToneLUT`+`adjustPixel`), Flou (`boxBlur`, l'ancien « Lissage », renommé pour qu'on le trouve), Inverser, Séparer RVBA (`rgbaSplit` : 4 sorties `image` en niveaux de gris, vignette 2×2), Combiner RVBA (`rgbaCombine` : 4 entrées optionnelles, R/V/B libres à 0 et A à 255, taille = première entrée branchée, les autres rééchantillonnées, une image en couleur compte pour sa luminosité ; Contours ne lit pas l'alpha, il n'est visible que dans les vignettes et via Séparer RVBA) → Contours (gradient ou Sobel, produit le `field`) → Sensibilité (pose `field.thresh` ; un Balayage en aval l'utilise **à la place** de son propre curseur, et l'indique dans son résumé ; bouton Auto = Otsu sur les magnitudes des pixels du masque ; vignette = le masque cyan de l'atelier) — à mettre sur une branche pour régler la sensibilité d'un seul calque → calques : Bande de teinte (plage qui peut boucler par le rouge + sat. min), Bande de luminosité, Clé couleur (même test RGB² que la pipette `pick`, clic sur l'aperçu pour prélever), Orientation (angle mod 180°, comme le split Sobel), Union (OU de deux masques) — tous avec « Exclure » ; un filtre ne fait que **rétrécir** `mask` (`narrow()`), une chaîne de filtres = un ET → Gamme (mini-clavier une octave degrés+fondamentale et bande piano des octaves à glisser, repris de l'atelier ; `octLow/octHigh` en params cachés), Balayage (sens/pas/sensibilité/courbe, même grille temps×hauteur que `process()`, seuil relatif au `maxEdge` de l'image entière comme dans l'atelier ; entrées optionnelles `curve` et `path` qui remplacent le menu Courbe / le Sens), Courbe perso. (carré lavande comme Trajet dessiné, `def.color` prime sur `CAT_COLOR`, 3 poignées à x=.25/.5/.75, monotone par construction — chaque poignée bornée par ses voisines ; « Partir de » copie une courbe prédéfinie ; les notes portent `customPts`, et tout passe par `stepFrac(tr,k)` → `curveFracAt(...,customPts)`), Trajet dessiné (dessin à la souris sur la vignette, image de fond optionnelle ; même modèle que l'atelier via `buildPathModel`/`pathProject`, table τ/ρ par pixel mise en cache sur le Balayage, points placés au centroïde des pixels de leur case), Octave (décalage d'octaves entières, la seule transformation de hauteur → aucune note hors gamme possible), Limiter (garde les N notes les plus fortes par pas) → Piste (instrument en icône comme l'atelier — `<select>` natif invisible par-dessus l'icône SVG dessinée — avec le nom écrit à côté ; liste `NODE_INSTR` = les 6 `GM_INSTR` + Pizzicato, sans icône pour l'instant, tuile « Pz » ; nom, couleur, muet) → Boucle (tempo/mesures/gate, ▶ synthé d'aperçu, export `.mid`, piano roll avec tête de lecture) → Logic (MIDI live), un par Piste (voir plus bas). Un Balayage sans Gamme branchée utilise la gamme par défaut de l'atelier (penta mineure, C, octaves 3-5).
- **Évaluation** : paresseuse avec cache, `markDirty(id)` invalide en aval, `scheduleRun()` recalcule en rAF puis redessine les vignettes des nodes touchés. Pas de cycle possible (`reaches()` refuse le branchement).
- **Lecture** : position tenue en fractions de boucle (`schedPos`/`schedAt`), planification juste-à-temps 25 ms / 150 ms comme ailleurs ; chaque piste a ses propres `steps`/`curve` (polyrythmie), relues à chaque tick → édition live. `togglePlay()` reste **synchrone** jusqu'au premier `osc.start()` (règle iOS). Un seul transport, deux sorties (`sink`) : le synthé (▶ de la Boucle) ou Web MIDI (node Logic) ; `playingLoopId` désigne toujours la Boucle jouée, `currentLoop()` la relit à chaque tick ; la tête de lecture s'affiche sur cette Boucle.
- **Node Logic (MIDI live)** — **un node par piste Logic, branché sur des `notes`** (demandes explicites : d'abord « 1er node Logic = piste 1, 2ᵉ = piste 2 » sur une Piste, puis « mets ça en Notes à la place de Track ») : entrée `notes` (sortie d'un Balayage, d'une Octave, d'un Limiter…), son propre **canal** (1-16, le prochain libre attribué à la création, modifiable même en cours de lecture) et son propre **port** (mémorisé par nom, sinon `/IAC|bus/i`, sinon le premier) — on sépare les pistes par canal sur un seul bus IAC, ou par bus. **Pas d'instrument ni de program change** : c'est la piste Logic qui choisit le son (et le Muet d'une Piste ne s'applique donc pas ici). Bouton **Panique** par node : note-off sur les 128 hauteurs × 16 canaux de chaque port + CC64/120/123 (pour ce que Dessons ne peut pas suivre, typiquement une piste Logic qui a cessé de recevoir en cours de note : sélection/armement changé pendant la lecture). Vérifié par un récepteur simulé (rejoue tous les messages par timestamp puis par ordre d'envoi) : 0 note tenue, 0 double note-on, sur stop, changement de canal en cours de lecture et rechargement de page, avec 2 nodes sur le même canal. - **Mesh 3D** (`srcMesh`) : source rendue, pas filmée. Formes intégrées (tore, nœud, cube, sphère bosselée) ou fichier `.obj`/`.stl` (`parseOBJ`/`parseSTL`, écrits à la main, normales `vn` respectées sinon lissées ; STL en facettes ; modèle centré, rayon 1). Trois `signal` : niveau (enveloppe de vélocité), hauteur, position. Type `signal` = `{at:pos=>0..1}`, pos = position dans la Boucle (0 à l'arrêt). Un node « Clip vidéo » (MIDI → vidéo 9:16) a été essayé puis abandonné sur demande (2026-11-06) : voir l'historique de la branche `midi-video`.

Menu d'ajout en onglets, dans l'ordre du signal : Sources, Retouche (fil `image`), Détection (`Contours` et tout ce qui filtre un fil `contours`, l'ancien onglet Calques), Musique, Signaux, Sortie, Outils (un par catégorie de `ADD_MENU`, le dernier ouvert est retenu, hauteur fixe pour ne pas sauter) : champ de recherche toujours focalisé, qui cherche dans tous les onglets (noms FR et EN quelle que soit la langue) ; ↑↓ dans la liste, ←→ ou Tab/Maj+Tab entre onglets, Entrée, Échap ; Tab (focus sur le fond) ou `/` l'ouvre au pointeur.

Ses réglages `panel:true` (sens, pas, sensibilité, courbe, mémoire) ne s'affichent pas sur le node, seulement dans Réglages et l'atelier ; l'atelier agit sur `readers(n)` : le node et tout Balayage encore branché à son `image` (anciens graphes, chaînes par couleur). Pour le reste : un trait = `{c, s, o, h, r, pts}` (couleur, taille à l'échelle de `DRAW_RES`, opacité, dureté, effet de la pression), `pts` en texte `x,y,pression,…` (1/10000ᵉ du canvas, 1/100ᵉ), décodé et mis en cache par `strokePoints()`, interné par trait dans l'historique. `drawAt()` redessine à n'importe quelle taille et jusqu'à n'importe quel point, avec une base en cache pour n'ajouter que le nouveau. L'estompe (`t:'s'`, `smudgeStamp()`) n'a pas de calque : elle porte un morceau d'image et travaille sur le canvas lui-même, `o` étant sa force ; c'est un trait enregistré comme les autres. Atelier `#drawEditor` par-dessus la zone de travail : le transport reste accessible ; `drawKey()` passe avant les raccourcis du canvas, son Cmd+Z agit sur les traits. Trait en cours : `n.drawLive`, repris dans `compute` toutes les 66 ms, sans passer par le cache de `drawAt()`. `drawOverlay()` montre la lecture sur la peinture (`#drawScan`, `mix-blend-mode:difference`). Replay : `startDrawReplay()` lance la Boucle et une horloge à part (`drawReplay`, durée `replayMin`), l'avancement ne suit plus `turns` ; la barre se clique ; à la fin, la Boucle continue et le node reprend ses propres réglages. Le rythme suit le nombre de points, pas le temps réel du geste. Calques d'affichage (`params.layers`, `syncDrawLayers()`) : canvases entre la peinture et `#drawScan`, en `multiply` sur papier clair et `screen` sur papier foncé, ce qui les place visuellement derrière la peinture sans rendre le dessin transparent ; jamais lus par `compute`. Mode Pixel (`params.grid`, 0 = normal, `PIXEL_GRIDS`) : par dessin ; un trait `t:'p'` garde sa grille `g` et sa taille `z` en cases, ses points sont les centres des cases, donc replay, Annuler et lecture en direct restent communs. `fillCells()` arrondit les deux bords de la même façon : aucune couture à aucune taille. `cellsBetween()` relie deux positions du pointeur. En mode Pixel, la grille est la partition : l'image porte `pixel:{g, bg}`, Contours le transmet dans le `field`, et le Balayage appelle `pixelNotes()` au lieu de sa détection : une case qui n'est pas entièrement la couleur de fond = une note (toute sa surface est lue, avec les mêmes arrondis que `fillCells()`, car un trait garde sa grille d'origine ; changer de grille recalcule les notes via `markDirty`), colonne = pas, ligne = degré de la gamme à partir de sa note la plus basse, sensibilité et nombre de pas ignorés, masque des filtres respecté. Un node qui recrée l'image entre le Dessin et Contours (Tons, Flou…) perd `pixel` et repasse en détection. Le sens de lecture se choisit aussi depuis l'atelier (`buildDirPicker()`) : c'est le paramètre `dir` de chaque Balayage alimenté par ce dessin, pas un réglage à part. Alpha : un dessin neuf a `bg:'transparent'`. L'image porte alors `alpha:true`, seul cas où Contours lit l'alpha (`al`) : un trait noir aurait sinon la luminosité du vide ; le papier vide est masqué, sauf le pixel d'arête juste avant la peinture, qui prend sa couleur. Gomme : `st.e`, `destination-out` sur transparent, couleur du fond sur papier opaque. Sur transparent, les calques d'affichage passent sous `#drawCanvas` en mode normal. Une image `drawn` a sa propre lecture : Contours compare aussi R, V, B et l'alpha, sur 3 pixels (deux couleurs de même clarté et un pinceau doux ont un contour), et le Balayage garde une échelle fixe (255), sinon le seuil monte à mesure que le dessin se remplit et les nouveaux traits ne s'entendent plus. Plancher absolu de 12 contre les résidus de gomme. Mémoire (`params.memory`, 0 = tout, `recentStrokes()`) : la grille temps×hauteur finit pleine (223 cases sur 240 à 60 traits), un nouveau trait n'y ajoute plus rien ; la musique lit alors les N derniers traits, la peinture reste entière à l'écran ; sans effet en mode Pixel. 8 dans le modèle Live painting. Sensibilité et sens se règlent depuis l'atelier : ce sont les paramètres des Balayages alimentés par ce dessin (`buildThreshSlider()`, `buildDirPicker()`) ; un pinceau très doux demande une sensibilité haute. Les autres sources gardent le seuil relatif de l'atelier. Compteur de l'atelier : notes de ce dessin et total de la Boucle, pour repérer une autre chaîne qui joue. - **Web MIDI temps réel** (bouton « Jouer dans Logic ») : boucle en direct vers un port virtuel, un canal par calque, planification juste-à-temps (les réglages s'entendent immédiatement). Chrome/Edge uniquement. `#midiPort` (le `<select>` de port) est `hidden` depuis que l'UI a été simplifiée : `refreshPorts()` auto-sélectionne déjà un port (`/IAC|bus/i` préféré, sinon le premier) dès que `ensureMidi()` résout, ce qui arrive au clic sur "Play in DAW" — le sélecteur manuel était redondant pour le cas courant (un seul port virtuel). - **Sustain (aperçu & MIDI)** (`#sustainToggle`, dans la section MIDI de `.panel-source`, juste au-dessus de l'accordéon « Comment connecter à Logic » — reste à cet endroit même si son effet dépasse maintenant le seul MIDI, le libellé le précise) : deux mécanismes bien distincts selon la sortie, ajoutés en deux temps (Web MIDI d'abord, sur demande explicite scopée à ce seul cas ; le synthé d'aperçu ensuite, l'utilisateur ayant testé et remarqué qu'il n'entendait aucune différence sans DAW). **Web MIDI** : envoie un vrai CC64 (pédale de sustain standard MIDI) — c'est Logic (ou tout instrument recevant le port virtuel) qui interprète le CC64 avec **son propre** moteur de sustain, Dessons ne simule rien côté audio, il relaie juste le contrôleur. `startPlayback('midi')` envoie CC64=127 sur chaque canal de `usedChannels` si la case est cochée au moment du clic sur "Play in DAW" ; un listener `change` dédié permet de l'actionner **en direct pendant la lecture** (équivalent d'appuyer/relâcher une vraie pédale). `stopPlayback()` envoie **toujours** CC64=0 sur `usedChannels`, indépendamment de l'état de la case — filet de sécurité pour ne jamais laisser une pédale engagée sur l'instrument recevant le port après l'arrêt de Dessons, ajouté à côté du nettoyage déjà existant (note-off explicites de `hangingNotes` + CC 120/123). **Synthé d'aperçu** : `scheduler()` calcule déjà `gateMs` (durée de note raccourcie par `Gate%`) pour caler `spawnVoice()` ; avec sustain coché et `sink==='synth'`, `synthDurMs` vaut `spanMs-3` (la pleine durée du pas) au lieu de `gateMs` — la note sonne sur tout son créneau plutôt que d'être coupée court par le Gate%. Ça seul s'est révélé **trop subtil pour s'entendre** (retour direct de l'utilisateur après test) : la plupart des timbres de `timbreFor()` ont un `sus` bas voire nul (les percussions/mallets type Vibraphone/Steel drums retombent quasi au silence pendant leur tenue) et un `rel` court, donc allonger juste la durée "note on" ne change presque rien à ce qu'on entend. Fix dans `spawnVoice(..., sustain)` (6ᵉ paramètre, `sustainOn` passé par `scheduler()`) : quand `sustain` est vrai, `rel = tb.rel*4` et `sus = Math.max(tb.sus, 0.55)` — un Vibraphone qui retombait au silence en 0.4s tient maintenant à 55% du volume et ne s'éteint qu'après 1.6s, un vrai effet de pédale de damper relevée plutôt qu'un simple prolongement de quelques dizaines de ms. `voices` (le tracking pour le plafond de 96 voix) n'a rien à changer : le nettoyage est piloté par l'event natif `osc.onended`, une release plus longue fait juste vivre l'entrée plus longtemps dans le `Set`, pas de fuite. Volontairement **pas** un vrai "tenu jusqu'au pedal-up" (qui empilerait des voix indéfiniment dans une boucle qui tourne en continu, jusqu'à un mur de son) — un compromis "durée+niveau+release boostés mais toujours bornés" plus sûr, sans changer le nombre de voix actives ni leur date de déclenchement. Le note-off réel envoyé en MIDI (`sink==='midi'`, `at + gateMs`) n'est **jamais** affecté par ce toggle : c'est le CC64 séparé qui gère la tenue côté DAW, pas le timing du note-off lui-même. Pas dans `PRESET_KEYS`/`CONTROL_DEFAULTS` : traité comme mute/solo, un réglage de performance éphémère plutôt qu'un paramètre de génération de la boucle.
- **Auto-play du synthé d'aperçu au chargement d'un média** (`autoStartPreviewOnLoad()`) : dès qu'une image/vidéo/webcam finit de charger (fin de `image.onload`, du `loadeddata` vidéo, du `ready()` webcam dans `loadFile()`/`toggleWebcam()`), la boucle démarre toute seule dans le synthé du navigateur — demande explicite de l'utilisateur pour ne plus avoir à cliquer « Écouter l'aperçu » à chaque fois. Réutilise `startPreviewPlayback()`, extrait du click handler de `#previewBtn` (même code exact, pas de logique dupliquée). Ne déclenche **jamais** si quelque chose joue déjà (`if(playing) return`) — n'interrompt pas un aperçu déjà lancé. Piège trouvé et corrigé : `loadFile()`/`toggleWebcam()` appellent déjà `stopPlayback()` sans condition en tout début de fonction avant de charger le nouveau média — donc `playing` est toujours redevenu `false` au moment où `autoStartPreviewOnLoad()` s'exécute, **même si une session Web MIDI réelle tournait vers Logic** juste avant. Sans garde-fou, déposer une nouvelle image pendant un jam MIDI aurait fait basculer silencieusement la sortie vers les haut-parleurs du navigateur. Fix : chaque fonction capture `wasPlayingMidi = playing && sink==='midi'` **avant** son propre `stopPlayback()`, et le passe en paramètre à `autoStartPreviewOnLoad(wasPlayingMidi)` — si la session coupée était du MIDI réel, l'auto-play est sauté, la lecture reste simplement arrêtée (comportement d'avant cette feature), sans tentative de reprendre le MIDI automatiquement (hors scope de la demande). Fiabilité par plateforme : repose sur le geste de chargement (clic Image/Vidéo/Webcam, ou un `drop`) qui compte encore comme activation utilisateur « récente » au moment où le média finit de charger — vrai en pratique pour un fichier local (quasi instantané) mais moins garanti que le clic direct sur `#previewBtn` ; la webcam est le cas le plus fragile (la popup de permission peut faire perdre cette fenêtre), et iOS Safari reste la plateforme la plus stricte. Si l'auto-play ne s'entend pas, `#synthState` (déjà l'outil de diagnostic existant) montre `ac.state` — même réflexe que d'habitude avant de deviner.
  - **Bug réel trouvé après coup : marchait pour l'image, jamais pour vidéo/webcam** (retour utilisateur direct). Cause : `startPreviewPlayback()` — partagée par le clic manuel et l'auto-play — refuse de démarrer si `lastNotes` est vide (`lastNotes.every(a=>!a.length)`), un garde-fou sain pour une image statique réellement vide (sensibilité trop stricte, image blanche…). Mais pour une source live, la toute première frame analysée (celle capturée pile au moment de `loadeddata` pour une vidéo, ou pile quand `v.videoWidth` devient non-nul pour une webcam) peut être légitimement vide ou quasi-noire (première frame décodée pas encore réellement affichable, ou readaptation d'exposition/mise au point de la caméra) — `liveLoop()` ré-analyse pourtant 15×/s et de vraies notes apparaissent une poignée de frames plus tard, mais l'auto-play est **une décision one-shot** prise à l'instant du chargement, donc voyait "rien à jouer" et renonçait pour de bon. Fix : `startPreviewPlayback()` calcule `isLive = srcKind==='video' || srcKind==='webcam'` et ignore le garde-fou "zéro note" pour ces deux cas — démarre le scheduler quand même, qui relit `lastNotes` en direct à chaque pas de toute façon, donc au pire un battement silencieux le temps que la vraie image arrive, jamais un blocage permanent. Une image statique garde le garde-fou intact (rien à jouer = rien à jouer, pour de vrai, pas de raison de démarrer dans le silence).

## Sécurité et tests

- **CSP** : `<meta http-equiv="Content-Security-Policy">` en tête des trois pages, `default-src 'none'` : rien ne peut sortir de la page (ni fetch, ni image distante), `eval` refusé. `'unsafe-inline'` reste nécessaire : tout le code est en ligne. Vérifié en `http` et en `file://`. Toute ressource externe ajoutée un jour devra y être déclarée, à éviter.
- **Fichiers ouverts** : un `.json` vient de n'importe qui. `validateGraph()` contrôle tout **avant** de toucher au graphe affiché (`cleanParams()` remet les curseurs dans leurs bornes, écarte les types inconnus et toute image qui n'est pas `data:image/`), `applyGraph()` fait le chargement et `loadGraph()` restaure l'ancien graphe si ça échoue. Sauvegarde auto impossible (`localStorage` plein) = message `#saveWarn` dans la barre du bas.
- **Capture** : webcam et micro sont coupés quand l'onglet est caché et reprennent seuls au retour (`releaseCapture()`/`resumeCapture()` dans Nodes, `resumeCamera()` dans l'atelier) ; une image figée reste figée. L'accès MIDI n'est demandé que sur un clic, jamais à l'ouverture d'un graphe (`.ccOn`). IndexedDB garde les 8 derniers fichiers 3D (`pruneMeshes()`). L'historique stocke chaque gros fichier une seule fois (`internBlob()`).
- **Tests** : `tests/index.html`, sans dépendance, à ouvrir via un serveur (`python3 -m http.server`, pas en `file://` : l'iframe y serait d'une autre origine). La page teste le vrai `nodes.html?test`, qui sauve sous une autre clé (`dessons.graph.test`) pour ne pas toucher au graphe de l'utilisateur. Les tests sont injectés par balise `<script>`, la CSP refusant `eval`. À lancer avant de publier, à compléter à chaque bug trouvé.

## Ce qu'il faut éviter de casser

- Le zéro-dépendance / zéro-build : ne pas introduire npm/webpack sans que ce soit une décision explicite et assumée avec l'utilisateur
- Le fait que ça reste utilisable en `file://` direct (double-clic) en plus de GitHub Pages
- La logique de gamme (aucune note hors gamme ne doit pouvoir sortir) — c'est un principe central du projet, pas un détail
- Le fait que l'export `.mid` marche sans Web MIDI : le mode temps réel est un bonus, jamais un prérequis. Si `navigator.requestMIDIAccess` est absent, le reste doit fonctionner normalement (seul le bouton « Jouer dans Logic » est désactivé). Idem webcam : si `getUserMedia` manque, image + vidéo doivent marcher.
- Pas de notes bloquées : tout ajout au scheduler temps réel doit garantir un note-off correspondant, et `stopPlayback()` doit rester le filet de sécurité (clear + note-off explicites + CC 123).
- La parité FR/EN : toute nouvelle chaîne visible passe par `I18N` (les deux langues) ou `[data-i18n]`, jamais en dur. `t()` pour le JS. Vérifier que `Object.keys(I18N.fr)` == `Object.keys(I18N.en)` — dans **les trois** pages (`compose.html` et `nodes.html` ont chacune leur propre dictionnaire, la langue est partagée via `dessons.lang`).
- Le nettoyage des sources : toujours passer par `stopSource()` avant d'en démarrer une autre (sinon caméra qui reste allumée, timers qui s'empilent).
