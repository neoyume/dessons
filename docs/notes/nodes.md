# Page Nodes (`nodes.html`)

Notes détaillées, à lire avant de toucher à cette partie. Les règles générales sont dans `CLAUDE.md`, à la racine. Le Dessin a ses propres notes : `dessin.md`.

Version modulaire de l'atelier : le même pipeline découpé en nodes reliés par des fils typés, sur un canvas qu'on déplace/zoome. L'atelier reste intact, c'est une 3ᵉ page. Le but : brancher, empiler et recombiner les étapes que l'atelier impose dans un ordre fixe (deux filtres de calque à la suite, un balayage par calque avec son propre sens/nombre de pas → polyrythmie, une gamme partagée par plusieurs balayages).

- **Types de fils** (couleur du port) : `image` `{w,h,data}` RGBA ≤ `MAXDIM` · `field` `{w,h,rgb,lum,hue,sat,edge,angle,maxEdge,mask}` (carte de contours + les pixels concernés) · `scale` `{pitches,scale,root}` · `notes` `{steps,curve,notes:[{step,midi,vel,row}],rows,field,dir}` · `track` = notes + `{name,program,color,mute}` · `path` `{points}` · `curve` `{pts}`. Une entrée n'accepte qu'un fil de même type ; seule l'entrée `tracks` de Boucle est multiple (ordre de branchement = ordre des canaux/pistes). Une `image` qui sort directement d'une Source porte aussi `{orig, region}` (le média pleine résolution + la zone affichée) : c'est ce qui permet au Recadrage de ré-échantillonner net.
- **Nodes** (`NODE_DEFS`, chacun `inputs/outputs/params/compute/thumb`) : Sources, trois nodes distincts (`srcImage` « Choisir une image » ; `srcVideo` « Choisir une vidéo » + Figer, ~15 fps ; `srcWebcam` Allumer/Éteindre + Figer, ~15 fps ; `srcMesh` voir plus bas ; Figer met aussi en pause l'élément `<video>`, sinon un Recadrage en aval relirait l'image en cours ; en-tête bleu pur `#0000ff`, `isSource(n)` les reconnaît, un graphe ancien de type `source` est relu en `srcImage`) → Recadrage (glisser sur la vignette, double-clic = image entière ; recadre le média d'origine **avant** la réduction à `MAXDIM` comme l'atelier, sinon — placé après un traitement — rogne les pixels reçus), Tons (noir/blanc/gamma/saturation, `buildToneLUT`+`adjustPixel`), Flou (`boxBlur`, l'ancien « Lissage », renommé pour qu'on le trouve), Inverser, Séparer RVBA (`rgbaSplit` : 4 sorties `image` en niveaux de gris, vignette 2×2), Combiner RVBA (`rgbaCombine` : 4 entrées optionnelles, R/V/B libres à 0 et A à 255, taille = première entrée branchée, les autres rééchantillonnées, une image en couleur compte pour sa luminosité ; Contours ne lit pas l'alpha, il n'est visible que dans les vignettes et via Séparer RVBA) → Contours (gradient ou Sobel, produit le `field`) → Sensibilité (pose `field.thresh` ; un Balayage en aval l'utilise **à la place** de son propre curseur, et l'indique dans son résumé ; bouton Auto = Otsu sur les magnitudes des pixels du masque ; vignette = le masque cyan de l'atelier) — à mettre sur une branche pour régler la sensibilité d'un seul calque → calques : Bande de teinte (plage qui peut boucler par le rouge + sat. min), Bande de luminosité, Clé couleur (même test RGB² que la pipette `pick`, clic sur l'aperçu pour prélever), Orientation (angle mod 180°, comme le split Sobel), Union (OU de deux masques) — tous avec « Exclure » ; un filtre ne fait que **rétrécir** `mask` (`narrow()`), une chaîne de filtres = un ET → Gamme (mini-clavier une octave degrés+fondamentale et bande piano des octaves à glisser, repris de l'atelier ; `octLow/octHigh` en params cachés), Balayage (sens/pas/sensibilité/courbe, même grille temps×hauteur que `process()`, seuil relatif au `maxEdge` de l'image entière comme dans l'atelier ; entrées optionnelles `curve` et `path` qui remplacent le menu Courbe / le Sens), Courbe perso. (carré lavande comme Trajet dessiné, `def.color` prime sur `CAT_COLOR`, 3 poignées à x=.25/.5/.75, monotone par construction — chaque poignée bornée par ses voisines ; « Partir de » copie une courbe prédéfinie ; les notes portent `customPts`, et tout passe par `stepFrac(tr,k)` → `curveFracAt(...,customPts)`), Trajet dessiné (dessin à la souris sur la vignette, image de fond optionnelle ; même modèle que l'atelier via `buildPathModel`/`pathProject`, table τ/ρ par pixel mise en cache sur le Balayage, points placés au centroïde des pixels de leur case), Octave (décalage d'octaves entières, la seule transformation de hauteur → aucune note hors gamme possible), Limiter (garde les N notes les plus fortes par pas) → Piste (instrument en icône comme l'atelier — `<select>` natif invisible par-dessus l'icône SVG dessinée — avec le nom écrit à côté ; liste `NODE_INSTR` = les 6 `GM_INSTR` + Pizzicato, sans icône pour l'instant, tuile « Pz » ; nom, couleur, muet) → Boucle (tempo/mesures/gate, ▶ synthé d'aperçu, export `.mid`, piano roll avec tête de lecture) → Logic (MIDI live), un par Piste (voir plus bas). Un Balayage sans Gamme branchée utilise la gamme par défaut de l'atelier (penta mineure, C, octaves 3-5).
- **Évaluation** : paresseuse avec cache, `markDirty(id)` invalide en aval, `scheduleRun()` recalcule en rAF puis redessine les vignettes des nodes touchés. Pas de cycle possible (`reaches()` refuse le branchement).
- **Lecture** : position tenue en fractions de boucle (`schedPos`/`schedAt`), planification juste-à-temps 25 ms / 150 ms comme ailleurs ; chaque piste a ses propres `steps`/`curve` (polyrythmie), relues à chaque tick → édition live. `togglePlay()` reste **synchrone** jusqu'au premier `osc.start()` (règle iOS). Un seul transport, deux sorties (`sink`) : le synthé (▶ de la Boucle) ou Web MIDI (node Logic) ; `playingLoopId` désigne toujours la Boucle jouée, `currentLoop()` la relit à chaque tick ; la tête de lecture s'affiche sur cette Boucle.
- **Node Logic (MIDI live)** — **un node par piste Logic, branché sur des `notes`** (demandes explicites : d'abord « 1er node Logic = piste 1, 2ᵉ = piste 2 » sur une Piste, puis « mets ça en Notes à la place de Track ») : entrée `notes` (sortie d'un Balayage, d'une Octave, d'un Limiter…), son propre **canal** (1-16, le prochain libre attribué à la création, modifiable même en cours de lecture) et son propre **port** (mémorisé par nom, sinon `/IAC|bus/i`, sinon le premier) — on sépare les pistes par canal sur un seul bus IAC, ou par bus. **Pas d'instrument ni de program change** : c'est la piste Logic qui choisit le son (et le Muet d'une Piste ne s'applique donc pas ici). Le tempo/mesures/gate viennent d'une Boucle (`midiLoopOf()` : la première atteinte en suivant les fils depuis la source des notes — en général notes → Piste → Boucle —, sinon la première Boucle du graphe) ; ▶ sur n'importe quel node Logic lance le transport de cette Boucle en `sink='midi'`, et `midiVoices()` joue à chaque tick tous les nodes Logic cadencés par elle, sur la même horloge, avec les notes relues sur leur entrée. Chaque node affiche ce qui manque (accès, port, notes, Boucle) ou « port · canal ». **Notes bloquées** (retour utilisateur : « parfois les notes restent coincées même si tout est sur pause ») — l'atelier programme chaque note-off d'avance (`send(..., at + gate)`), ce que la première version reprenait ; or tout ce qui attend dans la file de Chrome est perdu au rechargement / à la fermeture de l'onglet, et deux sources sur le même canal donnaient on, on, off, off. Désormais : `midiNoteOn()` n'envoie que le note-on, le note-off va dans `pendingOffs` et part seulement quand il entre dans la fenêtre de 150 ms (`flushNoteOffs(horizon)` en fin de tick) ; on/off **alternent strictement par (port, canal, hauteur), dans le temps ET dans l'ordre d'envoi** (`activeNotes` : même instant = une seule note ; sinon le note-off en attente de la note précédente part d'abord, à son heure ou juste avant la nouvelle si elles se chevauchent — un récepteur peut ignorer les timestamps) ; `pagehide` → `stopPlayback()`. `stopPlayback()` : `clear()` sur chaque port (sans effet dans Chrome), note-off pour chaque note-on déjà parti dans le futur (juste après son note-on), puis `midiAllOff()` = note-offs explicites (`hangingNotes` = `port|canal|note`) + CC64=0 + CC120 + CC123 sur chaque (port, canal) utilisé, anciens canaux compris — et une 2ᵉ fois 300 ms plus tard (sauf si une lecture MIDI a repris). Bouton **Panique** par node : note-off sur les 128 hauteurs × 16 canaux de chaque port + CC64/120/123 (pour ce que Dessons ne peut pas suivre, typiquement une piste Logic qui a cessé de recevoir en cours de note : sélection/armement changé pendant la lecture). Vérifié par un récepteur simulé (rejoue tous les messages par timestamp puis par ordre d'envoi) : 0 note tenue, 0 double note-on, sur stop, changement de canal en cours de lecture et rechargement de page, avec 2 nodes sur le même canal. Sustain = vrai CC64 par node, en direct. Le ▶ de la Boucle reste le synthé ; lancer l'un coupe l'autre. La Boucle n'a plus de sortie ; `loadGraph()` jette les fils dont un port n'existe plus (anciens graphes). Vérifié avec des ports simulés (pas avec un vrai Logic).
- **Mesh 3D** (`srcMesh`) : source rendue, pas filmée. Formes intégrées (tore, nœud, cube, sphère bosselée) ou fichier `.obj`/`.stl` (`parseOBJ`/`parseSTL`, écrits à la main, normales `vn` respectées sinon lissées ; STL en facettes ; modèle centré, rayon 1). Petit rendu WebGL maison, **un seul contexte** partagé (`meshGL()`), image `MAXDIM`² : normales en RVB, profondeur en alpha (0 = rien) — d'où l'intérêt de Séparer RVBA. Si WebGL manque, seul ce node reste vide (résumé `meshNoGL`). `turns` est **entier** (-4..4, tours par boucle) pour que la boucle retombe exactement sur ses pieds. `meshPhase()` = `schedPos % 1` (la position du scheduler, pas celle de la tête de lecture : un pas est lu sur l'image du moment où il est planifié), 0 à l'arrêt. **Export** : `bakeSpin()` refait le tour, réévalue le graphe à l'angle de chaque pas (`meshPhaseOverride`) et garde les notes de ce pas — le `.mid` correspond donc à ce qu'on entend, alors que le piano roll et le node Logic lisent l'image courante. Le fichier 3D n'est pas sauvé avec le graphe : `params.meshName` permet juste d'afficher « Fichier à recharger ».
- **Fichier MIDI** (`srcMidi`) : lit un `.mid` (`parseMidi()` dans `dessons-core.js` : carte de tempo, running status, un calque par piste+canal ; fichier gardé en base64 dans le graphe, c'est petit). Sort sur un fil `notes` normal (Octave, Limiter, Piste, Logic…) : le fichier entier = **un passage de la Boucle**, sur une grille fine (`MIDI_GRID` = 96 pas par mesure, garde 1/32 et triolets) ; les notes portent `len` (durée en pas, lu par le scheduler, l'export et le piano roll ; absent = 1 pas comme un Balayage). Le bouton « Caler la Boucle » (`matchLoop()`) donne à la Boucle la longueur et le 1ᵉʳ tempo du fichier et met son Gate à 100 %, sinon le morceau est compressé ou étiré dans ses mesures ; Boucle monte donc jusqu'à 64 mesures. **Exception assumée au principe de gamme** : un fichier importé garde ses hauteurs, rien ne le recale sur une gamme. Trois `signal` : niveau (enveloppe de vélocité), hauteur, position. Type `signal` = `{at:pos=>0..1}`, pos = position dans la Boucle (0 à l'arrêt). Un paramètre marqué `sig:true` gagne une entrée `sig_<id>` (ajoutée après `NODE_DEFS`) et `modParams()` **ajoute** le signal à la valeur du curseur sur toute son amplitude ; le node Plage (`sigRange`) réduit cette amplitude. Un node « Clip vidéo » (MIDI → vidéo 9:16) a été essayé puis abandonné sur demande (2026-11-06) : voir l'historique de la branche `midi-video`.
- **Organisation du canvas** : Reroute (`reroute`, une voie) et Attache-câbles (`cableClip`, une voie libre s'ajoute dès que la dernière est prise) laissent passer un fil sans le changer. Ports par instance (`portsIn(n)`/`portsOut(n)`, ids `i0`/`o0`, type dans `params.lanes`, `null` = libre, type `any`) : une voie prend le type de son premier fil (`typesFit()`), `syncLanes()` libère les voies débranchées (jamais pendant un glissé : `wireHeld`, sinon on détruit le port qui a la capture pointeur). Supprimer un de ces nodes recoud le fil. Double-clic sur un fil = reroute (`path.hit`, tracé transparent de 14 px ; un fil reste à sa place dans `links`, donc l'ordre des entrées multiples ne change pas). Sélection multiple : `selection` (Set), `selectedId` reste le dernier ; Maj+clic, Maj+glisser le fond ; un glissé déplace toute la sélection. Cadres de groupe : `frames`, couche `#frames` derrière les fils, `pointer-events:none` sauf titre et poignée, pour que le fond reste déplaçable à travers ; G ou « Grouper » encadre la sélection ; glisser le titre emporte les nodes dont le centre est dedans ; double-clic renomme ; sauvés dans le graphe. Menu d'ajout en onglets, dans l'ordre du signal : Sources, Retouche (fil `image`), Détection (`Contours` et tout ce qui filtre un fil `contours`, l'ancien onglet Calques), Musique, Signaux, Sortie, Outils (un par catégorie de `ADD_MENU`, le dernier ouvert est retenu, hauteur fixe pour ne pas sauter) : champ de recherche toujours focalisé, qui cherche dans tous les onglets (noms FR et EN quelle que soit la langue) ; ↑↓ dans la liste, ←→ ou Tab/Maj+Tab entre onglets, Entrée, Échap ; Tab (focus sur le fond) ou `/` l'ouvre au pointeur.
- **Générateur** (`srcGen`) : `phase` (entrée signal) et `turns` (cycles entiers par boucle, comme le Mesh, repris par `bakeSpin()`) ; `generateImage(p, t)` retombe sur la même image à chaque `t` entier : anneaux qui s'écartent, grille et dégradé qui glissent, bruit qui évolue sur place, en profondeur (3ᵉ axe du réseau refermé sur `NOISE_DEPTH` couches : les couleurs changent sans que rien ne glisse).
- **Sauvegarde auto** : en plus de `localStorage` (état courant, 5 Mo, repris au chargement), `autosave()` garde une version par minute si `snapshot()` a changé, dans IndexedDB (`dbStore()`, base `dessons-nodes` v2, stores `meshes`, `versions`, `versions-test`, `settings`, 30 versions). Elle fige le graphe de façon synchrone : l'appeler juste avant un remplacement (Nouveau, modèle, Ouvrir, Tout effacer, restauration) capture bien l'avant. Option fichier disque (File System Access, Chrome/Edge) : poignée gardée dans `settings`, à reconnecter d'un clic quand le navigateur redemande l'accès (`#saveState`). `pagehide` écrit ce qui attendait encore.
- **Modèles** (`TEMPLATES`, menu Fichier) : graphes de départ qui sonnent tout de suite grâce au Générateur, sauf « MIDI importé » qui attend un fichier. Mesh : le fichier 3D est gardé dans IndexedDB (base `dessons-nodes`, store `meshes`, clé `nom:taille`, séparée de la base des scènes pour ne pas toucher à `dessons-core.js`) et relu au chargement ; absent d'un `.json` ouvert ailleurs, d'où le message « Fichier à recharger » qui reste. Fichier MIDI à plusieurs pistes : une sortie `notes` par piste (`dynOut`, ids `L<n>`) en plus de la sortie générale. Un node lâché depuis la barre latérale sur un fil s'insère dessus s'il accepte ce type (`insertOnWire()`).
- **Maths de signaux** (onglet Signaux) : `time` sort la boucle, la mesure et le battement (0..1), les secondes et le numéro de frame ; tout repart à zéro à chaque boucle, pour qu'un passage sonne toujours pareil et que `bakeSpin()` puisse le rejouer. `math` : une opération de `MATH_OPS` sur A et B, fils ou nombres si débranchés ; résultat non fini = 0. `sigScale` : remap d'une plage vers une autre. Un fil `signal` peut porter n'importe quel nombre, pas seulement 0..1 : c'est le récepteur qui limite (`modParams()`, CC). `tags` sur un node = mots de recherche en plus.
- **Signaux** : sources `lfo` (cycles entiers par boucle, donc sans raccord ; sa valeur aléatoire vient de `hash01`, comme tout l'aléatoire des nodes : même résultat à chaque passage), `srcMic` (analyseur jamais relié aux haut-parleurs, `readMic()` dans la boucle à 15 fps, hors export) et `srcMidi`. `sigSource:true` = le node suit la Boucle : marqué sale pendant la lecture s'il a un fil `signal`, et repris par `bakeSpin()`, donc un LFO sur la sensibilité d'un Balayage s'entend aussi dans le `.mid`. `ccOut` : envoi dans le scheduler, seulement si la valeur change, quelle que soit la sortie choisie, tant que l'accès MIDI est ouvert (demandé à la création du node).
- **Nodes de notes** : `snapScale`, `degree` (échelle `scaleLadder()` : toutes les notes MIDI de la gamme), `merge` (grilles différentes réunies sur leur PPCM, plafonné à 3072 pas, via `stepFrac` pour respecter les courbes), `chance` (hash de la note et de la graine, pas un tirage), `echo` (retard en 32ᵉ de boucle, pour ne pas dépendre du nombre de pas), `euclid`. Une note par (pas, hauteur) après chacun : `uniqueNotes()` garde la plus forte.
- **En-tête et transport** : menu Fichier (`#fileMenu` : Nouveau, Ouvrir, Sauver, modèles), panneau `?` (`#helpPanel`, lignes dans `helpRows`, un tableau dans `I18N`), barre `#transport` en bas : lecture, tempo, mesures, position, export, Logic. Elle pilote `transportLoop()` (la Boucle jouée, sinon la sélectionnée, sinon la première) et réutilise `togglePlay()`/`toggleMidi()`/`exportLoop()` ; `syncTransport()` la tient à jour. Espace = lecture/stop.
- **Annuler / copier** : `historyCommit()` prend un instantané (`serialize()` sans la vue, 60 max) au moment où le graphe se stabilise, dans `saveSoon()` : un glissé de curseur = une étape. `applySnapshot()` applique un diff, pas `loadGraph()`, pour qu'un node encore présent garde sa vidéo, sa webcam ou son mesh ; un node vidéo/webcam supprimé puis restauré revient vide. Cmd+C/X/V/D : nodes sélectionnés et fils internes (`copySelection()`, `pasteNodes()`), un node Logic copié prend le prochain canal libre.
- **Barre de nodes** (`#nodeBar`, dans l'en-tête entre Fichier et + Node) : un menu déroulant par catégorie de `ADD_MENU`, reconstruit par `buildNodeBar()` à chaque `setLang()`. Clic = ajout au centre, glisser = ajout au point de dépôt ou sur un fil (`itemDrag()`) ; pendant un glissé le menu passe en `.dragging` (invisible, `pointer-events:none`) sans être masqué, car il tient la capture du pointeur. Survoler la barre avec un menu ouvert change de menu.
- **Panneau Réglages** (`#propsPanel`, à droite de `#stage` dans `#workspace`) : `renderProps()` remet les curseurs du node sélectionné avec le même `paramEl()`, `syncTwins()` tient à jour les deux exemplaires d'un paramètre (`data-param`) ; les réglages sur mesure (clavier de Gamme, port MIDI…) restent sur le node. En bas, `paintPreview()` redessine la vignette du node sélectionné dans `#previewCanvas` en échangeant `n.thumb` le temps de `drawThumb()`. Bouton « Réglages » (`panelToggle()`), état dans `localStorage['dessons.props']` ; ouvert par défaut sauf sous 700 px, où il passe en surimpression.
- **Entrées `signal`** : posées au bord du node à côté de leur curseur (`paramEl()`), pas dans la colonne des ports. **Repli** : bouton ▾ de l'en-tête, `n.params.folded` ; un node replié garde visible ce qui est encore branché (`:has(.port.linked)`), sinon le fil n'a plus où arriver.
- **Pizzicato** (`PIZZ_PROGRAM` = 45, GM « Pizzicato Strings ») : synthèse Karplus-Strong, propre à `nodes.html` pour l'instant (pas d'icône dessinée → pas encore dans l'atelier). `pluckBuffer()` rend la corde une fois par (hauteur, 4 niveaux de brillance selon la vélocité) dans un `AudioBuffer` mis en cache ; pas d'AudioWorklet (fichier séparé, fragile en `file://`). Piège corrigé : la boucle `d[i]=ring[p]; ring[p]=avg(ring[p], ring[p+1])` a une période de **N − 0,5** échantillons (pas N + 0,5) ; N entier + `playbackRate` = juste à 0 cent sur toute la tessiture (mesuré). Perte par passage réglée pour que toutes les hauteurs s'éteignent en `PIZZ_T60` (0,32 s), excitation = bruit passe-bas (doigt, pas médiator), corps = cloche à 450 Hz + passe-bas 4,2 kHz. `playPluckVoice()` renvoie `{osc, g, sub}` comme `playSynthVoice()` → `fadeOutVoice()` et le plafond de voix marchent tels quels.
- **Rangement de l'interface** (2026-11-07) : en-tête = Fichier + ↶↷ à gauche, catégories, puis + Node, Réglages, ?, langue ; `#viewBar` (Cadrer, Grouper, zoom %, clic = 100 %) posé sur le canvas, dans `#workspace` et pas `#stage` (qui prendrait le pointeur pour déplacer la vue). Vignette sans contenu : `emptyThumb()` pose `.empty`, le bloc disparaît ; `scheduleRun()` retrace les fils si ça change, sans lire de hauteur par node (15 fps). `def.note` n'est plus dans le node : pastille `i` (tooltip) dans l'en-tête, texte complet en tête de Réglages. Rien de sélectionné : `renderStart()`, les modèles dans l'ordre de `TEMPLATE_KEYS` avec une ligne chacun (`tplDesc_*`) ; `TEMPLATE_KEYS` est déclaré haut dans le fichier parce que `renderProps()` peut tourner avant `TEMPLATES`. Écran de dessin : `.drawHead` et `.drawFoot` hors de la zone qui défile (Terminer et Tout effacer restent visibles sur une fenêtre basse), sections `<details>` Outil / Couleur / Lecture / Calques, repli dans `localStorage['dessons.drawFolds']`. `body.drawing` masque les outils du graphe : ils agiraient derrière l'écran, et ↶ de l'en-tête annule le graphe alors que Cmd+Z annule les traits. Un clic souris retire le focus du bouton, sinon Espace le représse au lieu de lancer la lecture. Vignette d'une image `alpha` sur papier clair, sinon un trait noir ne s'y voit pas.
- **Export** : `buildLoopMidi()` = même calcul de ticks que `buildMidi()` de l'atelier, une piste par node Piste branché.
- **Persistance** : graphe dans `localStorage['dessons.graph']` (`{app:'dessons-nodes', v:1, nodes, links, view}`), sauvé en différé à chaque changement ; l'image source y est gardée en JPEG à la taille d'analyse (`params.img`), pas la vidéo/webcam. Sauver/Ouvrir `.json` pour changer de navigateur. « Nouveau » recharge `defaultGraph()` (Source → Tons → Contours → 2 bandes de luminosité → 2 balayages 8/16 pas → Octave −1 → Basse synthé + Vibraphone → Boucle).
- **Interaction** : glisser le fond = déplacer, pincer / ctrl+molette = zoom, molette = défiler ; double-clic ou clic droit = menu d'ajout ; tirer un fil depuis une sortie, ou depuis une entrée vide (`draft.toNode`, classe `body.rev` : vers une sortie compatible, ou dans le vide pour le menu filtré sur les nodes qui produisent ce type) ; attraper une entrée branchée décroche son fil ; lâcher un fil dans le vide ouvre le menu filtré sur les nodes qui acceptent ce type et branche automatiquement ; Suppr efface le node sélectionné ; déposer un fichier : sur une source (si elle n'est pas du bon genre, `sourceFor()` la remplace sur place en gardant ses fils), sinon la source sélectionnée/la première du bon genre, sinon une source vide (qui change de genre), sinon un nouveau node.
- **Pistes suivantes** : icône Pizzicato (puis le porter dans l'atelier/la Chanson via `dessons-core.js`), autres instruments Karplus-Strong (harpe, guitare), « Ajouter à la chanson » (le format de scène suppose un seul `steps` pour toute la boucle → à adapter pour la polyrythmie).
